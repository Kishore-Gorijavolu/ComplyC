# Compiler Extension Sanitizer

The Compiler Extension Sanitizer is part of the current ComplyC parser architecture. Its purpose is to normalize compiler-specific C extensions into pycparser-friendly C without modifying the user's original source files.

## Why it exists

Embedded C projects often contain compiler extensions generated by vendor tools or required by the toolchain. Examples include GCC `__attribute__((section(...)))`, interrupt-handler annotations, weak symbols, packed structures, memory-section pragmas, and inline assembly.

These constructs are valid for the target compiler, but pycparser does not understand them. Without sanitization, ComplyC may skip valid embedded source files due to parser errors.

## Current responsibilities

The sanitizer currently handles:

- GCC/Clang `__attribute__((...))`, including nested arguments such as `section(".main_function")`
- `__extension__`, `__inline__`, `__restrict__`, and related double-underscore keywords
- common embedded markers such as `__weak`, `__irq`, `__packed`, `__root`, and `__ramfunc`
- basic `__declspec(...)`, `__interrupt(...)`, and `__ISR(...)` forms
- line-preserving removal of basic pragma and inline assembly constructs

## Parser flow

```text
Source file
  -> GCC or built-in preprocessing
  -> Compiler Extension Sanitizer
  -> pycparser AST
  -> Source Mapping / Source Index / Rule Engine
```

## Design rule

The sanitizer should remove or normalize only syntax that prevents parsing. It should preserve surrounding function and declaration syntax so ComplyC can still report useful source locations.

## Future enhancements

Future versions can split the sanitizer into compiler-specific profiles:

- GCC / Clang
- IAR
- Keil / Arm Compiler
- TI
- Microchip XC

For now, the project uses one consolidated module: `complyc/compiler_extensions.py`.
